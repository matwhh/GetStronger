# Get Stronger

Особистий інструмент для тренувань і харчування: план у залі з робочими
вагами, розрахунок калорій і макронутрієнтів, журнали прогресу й сезонний
рейтинг за регулярність.

Нічого не продає, реклами й підписок немає, дані нікуди не передаються.
Уся математика — з відкритих джерел, кожен висновок має посилання на PubMed
на сторінці «Дослідження».

**Статичний сайт без збірки.** Клонувати й відкрити `index.html` — цього
достатньо. Ні webpack, ні Vite, ні npm-залежностей на фронтенді немає.

## Що вміє

| | |
|---|---|
| **Тренування** | Схеми під 3–6 днів на тиждень, робочі ваги й повторення по кожній вправі, підходи в реальному часі, таймер відпочинку, журнал сесій |
| **Періодизація** | Цикл на 8–16 тижнів від % разового максимуму, з розвантажувальними тижнями |
| **Харчування** | Норма калорій і макросів (Mifflin-St Jeor або Katch-McArdle), розклад на прийоми їжі, довідник продуктів, рецепти на контейнери |
| **Прогрес** | Вага тіла, сила, тренування, харчування; прогноз проти факту, особисті рекорди, теплокарта |
| **Рейтинг** | Сезонний ELO за регулярність. Рахується на сервері й підробці з браузера не піддається |
| **Трекери** | Сон, кроки, вода, самопочуття, заміри тіла, добавки, звички — з власними цілями. Живуть на «Сьогодні», налаштовуються на «Трекерах» |
| **Ввід за день** | Тренування й вага — на власних сторінках із календарем: позначити день або дописати пропущене одним дотиком |
| **Довідка** | Контекстна: одна книжка в шапці, вміст залежить від розділу |
| **PWA** | Ставиться на домашній екран, працює без мережі, синхронізується між пристроями |
| **Оформлення** | Одна темна тема. Інтерфейс монохромний — колір є лише в даних і станах (макроси, групи мʼязів, «в нормі / увага») |

Форматів даних два: `localStorage` завжди і Supabase — коли ви ввійшли.
Без акаунта працює все, крім рейтингу.

## Із чого зроблено

Список короткий, і це навмисно.

**Фронтенд**
- HTML, CSS, JavaScript (ES2020, `window.*`-модулі, без бандлера)
- Service worker (`sw.js`) — власний, ~200 рядків, без Workbox
- Шрифти з Google Fonts, більше жодних зовнішніх ресурсів

**Бекенд**
- [Supabase](https://supabase.com): Postgres, GoTrue (авторизація), PostgREST, pg_cron
- Уся економіка рейтингу — у функціях Postgres, не в клієнті
- Row Level Security на кожній таблиці, з `FORCE`

**Інфраструктура**
- Vercel — статичний хостинг
- GitHub Actions — тести, гігієна, браузерні перевірки
- Sentry — помилки клієнта (без пошти, токенів і даних профілю)

**Розробка**
- Node 22 — лише для тестів і скриптів; на сайт не потрапляє
- Вбудований `node --test` — 1098 юніт-тестів, нуль залежностей
- Playwright — 46 браузерних наборів на справжньому Chromium
- `tools/ci-hygiene.mjs` — 16 перевірок того, чого не видно оком

## Як запустити

Збірки немає. Достатньо:

```bash
git clone https://github.com/matwhh/GetStronger.git
cd GetStronger
open index.html          # або просто подвійний клік
```

Для тестів і скриптів потрібен Node 22:

```bash
npm test                        # 1098 юніт-тестів, залежностей немає
node tools/ci-hygiene.mjs       # гігієна репозиторію, 16 перевірок
```

Для браузерних перевірок — Playwright:

```bash
npm i playwright && npx playwright install chromium
bash tools/ci-browser.sh core   # 14 наборів, ~8 хв
bash tools/ci-browser.sh full   # усі 46, ~50 хв
```

## Налаштування

Єдиний файл налаштувань — [`js/config.js`](js/config.js):

```js
window.APP_CONFIG = {
  siteName: 'Get Stronger',
  siteUrl:  'https://приклад.вашдомен',   // для og:url у картці месенджера
  supabase: { url: '', anonKey: '' }      // порожні = локальний режим
};
```

**Порожні ключі Supabase — це робочий стан, а не недоробка.** Get Stronger працює
локально: усі дані в цьому браузері, синхронізації між пристроями й
рейтингу немає, решта працює повністю.

**`anonKey` публічний за задумом.** Це не витік і не помилка: доступ до
даних обмежують політики RLS у Postgres, а не таємність ключа. Ховати його
в змінних оточення для статичного сайту неможливо (він усе одно поїде в
браузер) і безглуздо. Справжні секрети — `service_role`-ключ і паролі — у
репозиторії не зустрічаються ніде; за цим стежить `tools/ci-hygiene.mjs`.

Змінних оточення проєкт не використовує.

між `db/*.sql` і бойовою схемою.

## Як користуватись

1. **Перший запуск.** Дата народження (є вікова межа), потім зріст, вага,
   активність і стаж — без них не рахуються ні калорії, ні план.
2. **Обрати схему** на «Планах тренувань» під кількість днів, які ви
   реально ходитимете.
3. **Проставити робочі ваги** в «Моєму плані тренувань» — без них екран тренування
   не має що показати.
4. **У залі** — «Тренування»: тапати квадратики підходів. Усе інше
   (журнали, рейтинг, статистика) заповнюється саме звідси.
5. **Харчування** — «Раціон»: додавати продукти, дивитись на смугу до цілі.

Не розумієте екран — натисніть книжку в шапці. Довідка контекстна: на
кожній сторінці вона про цю сторінку.

## Архітектура

**Ядра, інтерфейс, шар даних.** `js/*-core.js` — чисті функції без DOM;
сторінкові файли малюють; `js/store.js` — єдина точка доступу до профілю
(`getProfile` / `saveProfile` / `onChange`). Сторінка ніколи не пише в
сховище напряму.

**Сервер — авторитет для рейтингу.** Клієнт показує оцінку одразу, щоб не
чекати відповіді, але істина — те, що повернула база. `elo_submit` не
вірить жодному числу від клієнта: він сам шукає факт у профілі
користувача. Тому підправити рейтинг у браузері неможливо в принципі, а не
складно.

**Офлайн — не режим, а норма.** Профіль завжди в `localStorage`; невдалі
записи лягають у підписану чергу й досилаються самі. Service worker
віддає HTML із мережі з тайм-аутом 4 с, JS і CSS — теж із мережі, з
тайм-аутом 2 с, і лише решту статики зі stale-while-revalidate. Код
навмисно не на SWR: той віддає попередню версію, і публікація, що чіпає
самі стилі чи скрипти, доїжджала б до людини лише з другого відкриття.

**Схема бази — у репозиторії.** `db/live-schema.sql` — знімок продакшену,
який генерується запитом `db/dump-live-schema.sql`. Зміни тільки
міграціями; CI розгортає знімок у тимчасовий Postgres і ганяє по ньому
92 SQL-перевірки й перевірку прав.

**Оформлення — пласка мова застосунку.** Одна темна тема: пласкі
поверхні, межа 1px як головний засіб розділення, радіуси 8–14px, тінь
лише в того, що справді висить над сторінкою — модалок, тостів, таймера,
випадного меню. Стан елемента показує фон і межа, а не напрямок світла.

**Колір позначає дані й стан, а не оздоблює інтерфейс.** Поверхні, текст,
межі, кнопки, посилання й календарі лишаються монохромними. Сім відтінків
(`--c-*` у `css/style.css`) — це словник, а не тема: у кожного є значення,
і без значення він не вживається. Зараз ними говорять три речі:

- **макронутрієнти** — білок, жири, вуглеводи, клітковина (до цього три
  сірих і штрихована клітковина: сусідні заливки давали 2,8:1 одна до
  одної при нормі 3:1, і розсунути їх по яскравості було нікуди);
- **групи мʼязів** — за регіоном (жим / тяга / ноги / корпус), бо груп
  девʼятнадцять і девʼятнадцять відтінків не розрізнить ніхто;
- **стани** — «в нормі», «увага», «вище межі».

Кожен відтінок проходить 4,5:1 на всіх трьох поверхнях проєкту, а всі 21
пара — ΔE ≥ 25 у Lab, тобто вони відрізняються не яскравістю, а кольором.
Стереже `tools/verifythemes.mjs`; він же валить збірку, якщо колір
протече в основу. Червоний і зелений стоять поруч лише там, де елемент
підписаний словами: колір ніде не єдиний носій сенсу.

До вересня 2026 тут був неоморфізм — пари зустрічних тіней, втоплені
поля, радіуси до 28px. Він прибраний свідомо: на майже чорному тлі темна
половина пари невидима, тож різницю між звичайною, наведеною й натиснутою
кнопкою тримала одна грань у 5% білого, і читалась вона гірше за просту
рамку. Плюс він коштував місця: 32px відступу в картці й великі проміжки
під розмиття — на телефоні це половина екрана під повітря в застосунку,
який показує таблиці й поля.

Уся мова живе в токенах `css/style.css` (секція «ШАР ЗАСТОСУНКУ»): тіні
вживаються приблизно в пʼятдесяти правилах, і саме тому перехід звівся до
зміни значень, а не до пʼятдесяти окремих рішень.

**Теплокарта каже, скільки, а не лише «чи був».** Клітинка дня несе
рівень 0–4, похідний від частки закритих підходів — тобто рівно від того,
за що нараховує рейтинг. Ручна позначка («тренувався, але підходів не
записував») має власний вигляд — контур без заливки: ставити її на ту
саму шкалу означало б сказати про день те, чого в даних немає. Кроки
показує яскравість, не колір: зелена шкала теплокарт — класична пастка
для дальтоніків, у якій сусідні кроки не розрізняються.

**Скло тільки там, де є що заломлювати** (як воно зроблене — [`docs/GLASS.md`](docs/GLASS.md)). Картки вибору програми —
єдине місце з нахилом за курсором, бликом і напівпрозорою поверхнею. Під
сіткою для цього лежить власне світло: сторінка в Get Stronger майже чорна й
рівна, і `backdrop-filter` над нею не малює нічого, лише тримає окремий
шар композиції. На дотику ефекту немає взагалі — курсора там немає, а
розмиття на слабкому залізі коштує найдорожче.

**Один перемикач — один механізм.** Сегментований вибір (`.seg`) будують
вісім місць у пʼятьох файлах; позицію білого виділення рахує `js/app.js`
і кладе в CSS-змінні, а малює й анімує сам CSS. Копія механізму в кожному
місці розійшлася б із рештою на першому ж правленні.

**Повторення: діапазон як типове, число як вибір.** Схема дає діапазон,
похідний від стажу і розміру цільової групи (`js/reps-core.js`): 8–10 і
10–12 новачкові, 6–8 і 8–10 досвідченому. У «Моєму плані тренувань»
діапазон можна замінити точним числом, і саме воно потрапляє в підхід на
екрані тренування — доти туди підставлялась середина діапазону, тобто
число, якого людина ніде не задавала.

Власне число обмежене згори: **12 повторень на вправу для великої групи
(груди, спина, квадрицепс, біцепс стегна, сідниці) і 15 для малої.** Вище
поле поставити не дає, а значення, що приїхало з іншого пристрою або з
відредагованого руками експорту, підтягується до стелі при читанні. В
інтерфейсі про цю межу не написано нічого й ніде — це рамка, а не
правило, яке треба памʼятати; єдина її документація — цей абзац.
Діапазони таблиці в неї вміщаються цілком (найвище число там — 12), тож
стеля не забирає нічого з того, що програма пропонує сама.

**Тести — там, де були помилки.** 998 юніт-тестів, 46 браузерних наборів,
92 SQL-перевірки. Кожен тест із позначкою «регресія:» стоїть на місці
реальної помилки — перш ніж «спрощувати», подивіться, що саме він стереже.

## Обмеження

Чесний перелік. Не «на майбутнє», а те, як є зараз.

- **Get Stronger не бачить, ЯК ви робите вправу.** Техніка, глибина, біль — поза
  системою. Він працює з тим, що ви відмітили.
- **Не медичний сервіс.** Калорії, макроси, пульсові зони, ІМТ, 1ПМ —
  оцінка за формулами на середніх людях, не призначення.
- **Немає інтеграцій.** Ні Apple Health, ні Google Fit, ні годинників, ні
  вагів. Сон і кроки вводяться руками.
- **Реєстрація ручна.** Заявку схвалює адміністратор. Це не масовий сервіс.
- **Один інтерфейс, одна мова.** Українська. Локалізації немає.
- **Резервних копій Supabase немає** на Free-плані: єдина копія — щоденний
  дамп на компʼютері власника. Процедура відновлення — `db/RESTORE.md`.
- **Останній тиждень сезону й закриття сезону** поки що потребують ручного
  виклику (див. `db/README.md`).
- **Перевірено лише в Chromium.** Safari й Firefox не тестувались
  автоматично: у контейнері доступний тільки Chromium.
