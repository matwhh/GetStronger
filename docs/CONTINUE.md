# Як продовжити роботу

Цей файл — для моменту, коли ти повертаєшся до проєкту через місяць і не
памʼятаєш нічого. Або коли відкриваєш новий чат і треба ввести нейронку в
курс справи за одну хвилину.

Він не переказує `AGENTS.md` (правила) і не переказує `docs/MAP.md` (де
що лежить) — два описи одного розходяться на першій же правці. Він дає
**мисленнєву модель** і **порядок дій**.

---

## 0. Проєкт за шістдесят секунд

**Get Stronger** — особистий інструмент для тренувань і харчування. План у
залі з робочими вагами, калорії й макроси, журнали прогресу, сезонний
рейтинг за регулярність. Не продукт на продаж: реєстрація ручна, заявку
схвалює адміністратор.

Три речі, з яких випливає майже все інше:

1. **Статичний сайт без збірки.** Немає webpack, Vite, npm-залежностей на
   фронтенді. `index.html` відкривається подвійним кліком і працює.
   Модулі спілкуються через `window.*`, порядок `<script defer>` у
   розмітці = порядок виконання. Коментарі в коді розлогі навмисно: вони
   коштують кілобайтів, а не читабельності, і мініфікація забрала б їх в
   обмін на неможливість подивитися, що всередині.
2. **Три шари.** `js/*-core.js` — чисті ядра без DOM (33 файли,
   ~10 000 рядків, під юніт-тестами). Сторінкові файли (`js/today.js`,
   `js/journal.js`, …) малюють. `js/store.js` — ЄДИНА точка доступу до
   профілю (`getProfile` / `saveProfile` / `onChange`). Сторінка ніколи
   не пише в сховище напряму.
3. **Сервер — авторитет для рейтингу.** Клієнт показує оцінку одразу, але
   істина — те, що повернула база. `elo_submit` не вірить жодному числу
   від клієнта: він сам шукає факт у профілі. Підправити рейтинг у
   браузері неможливо в принципі, а не складно.

**Де лежать дані.** Один JSON у `localStorage` під ключем `ib.profile` —
і він же в Postgres у колонці `jsonb`, якщо людина ввійшла. Журнали
всередині профілю: `weightLog` (вага), `sessions` + `days` (тренування),
`measureLog` (заміри), `trackers`/`trackerLog`, `mealsLog`. Усі ключовані
МІСЦЕВИМ днем `YYYY-MM-DD`.

**Три джерела правди, які не можна дублювати** (за цим стежить гігієна):

| Модуль | Що вирішує | Хто кличе |
|---|---|---|
| `js/date-core.js` | ключі днів, зсуви, різниці | усі, хто рахує дати — решта має лише делегати в один рядок |
| `js/daylog-core.js` | чи був тренувальний день, як пишеться вага | «Сьогодні», «Дні тренувань», «Зважування», «Прогрес» |
| `js/tracker-core.js` | реєстр трекерів, записи, стріки, закріплення | «Сьогодні» й «Трекери» |

## 4. Робочий цикл

Один і той самий, завжди:

```bash
# 1. змінив код

node --check js/файл.js       # синтаксис, миттєво
npm test                      # 998 юнітів, ~6 с
TZ=Europe/Kyiv npm test       # той самий набір в іншому поясі
node tools/ci-hygiene.mjs     # 16 перевірок гігієни, ~1 с

# 2. якщо чіпав те, що видно на екрані:
node tools/verify<щось>.mjs   # одна перевірка, 10–60 с
bash tools/ci-browser.sh core # 13 найважливіших наборів, ~8 хв

# 3. кнопка «Опублікувати.command»
```

**Правило, яке рятує найчастіше: нова перевірка мусить ВПАСТИ без твого
виправлення.** Написав тест — зламай виправлення, переконайся, що тест
червоний, поверни. Тест, який ніколи не був червоним, не стереже нічого.

**Один коміт — одна думка.** Тіло коміту пояснює причину: що було не так,
чому саме так полагоджено. Через півроку це єдине, що лишиться від
міркувань.

## 5. Пастки цього репозиторію

Те, на чому вже втрачали час. Кожен пункт коштував щонайменше півгодини.

| Пастка | Як виглядає | Що робити |
|---|---|---|
| Тест не бачить дат | `TypeError: Cannot read properties of undefined` у ядрі | у `loadModules([...])` **першим** має стояти `'js/date-core.js'` — решта ядер має лише делегати |
| `assert.deepEqual` падає на однакових масивах | «Expected values to be strictly deep-equal» без видимої різниці | масиви з пісочниці `node:vm` мають ІНШИЙ `Array.prototype`. Порівнюй `.join(',')` |
| Перевірка червоніє раз на пʼять прогонів | «та це випадковість» | найгірший вид червоного: його списують. Приклад — `verifyworkout` питав `href` у картки дня, а у вихідний картка навмисно `<div>`. Лікується вибором конкретного дня, а не «першого-ліпшого» |
| Якір не доводить до блоку | сторінка стоїть на початку | блоки журналу порожні на завантаженні: «прокрутка зупинилась» справджується миттєво на нулі. Спершу чекай, доки блок отримає висоту |
| Другий `goto` на ту саму сторінку нічого не робить | перевірка міряє попередній стан | два `goto`, що різняться лише якорем, браузер вважає переходом усередині документа. Між ними — `goto('about:blank')` |
| `.command` не запускається з Finder | «немає відповідних привілеїв» | файл приїхав із хмари як 0644. Біт виконання треба поставити і в ІНДЕКСІ: `git update-index --chmod=+x «файл»`. Стереже перевірка 12 гігієни |
| Гігієна лається на мертвий CSS | «правило під клас, якого ніде немає» | перевірка 16. Новий клас має бути вжитий у JS або HTML — інакше він мертвий за визначенням |
| Дата «зʼїхала на день» | «вчора» стало «сьогодні» двічі на рік | дві шкали: ключ дня — МІСЦЕВИЙ, різниця днів — В UTC. Місцева доба переходу на літній час триває 23 години. Пояснено в `js/date-core.js` |
| Змінна з функції не долетіла | у bash-скрипті значення порожнє | присвоєння всередині функції, викликаної через `$(...)`, живе в підоболонці й не повертається в батька |
| CI червоний на кожному пуші | локально все зелене | крок залежить від того, чого на раннері немає за визначенням. Розрізняй «пропущено» (можна було перевірити, середовище не дало — валить збірку) і «не застосовно» (обʼєкта перевірки тут не існує — не валить). Приклад: справжня резервна копія лежить поза репозиторієм і в CI не буває ніколи |
| Червоний CI, який червоний завжди | його перестають читати за два дні | і далі він ховає все, що падає після нього. Прогін #103: чотири кроки після зламаного не виконувались із 7 вересня жодного разу |

## 6. Що живе поза репозиторієм

Код — це не весь проєкт. Три сервіси, до яких потрібні акаунти власника:

| Сервіс | Що там | Коли треба лізти |
|---|---|---|
| **Supabase** (`sojbyoxcxyiollefupss`) | база, авторизація, рейтинг, `pg_cron` | міграції, тексти листів, адреси перенаправлення |
| **Vercel** | хостинг | нічого робити не треба: збирає сам на кожен пуш у `main` |
| **Brevo** | надсилання листів (SMTP для Supabase) | майже ніколи |

Правила зміни бази — `db/README.md`. Коротко: **у продакшені руками нічого
не міняють**, усе через файл міграції, і `db/live-schema.sql` оновлюється
після.

**Поруч із репозиторієм на диску** лежать теки, яких у git немає навмисно
— вони або важкі, або з робочими матеріалами. Шукати їх у репозиторії
марно, вони в `~/Desktop/Get Stronger/`:

| Тека | Що там |
|---|---|
| `backups/` | щоденний дамп Supabase. На Free-плані це ЄДИНА резервна копія; процедура відновлення — `db/RESTORE.md` |
| `Листи для Supabase/` | чотири готові шаблони листів + «ЯК ВСТАВИТИ.txt». Вставляються руками в Authentication → Emails |
| `Іконки/` | джерела знака: SVG, PNG 4K, зразки |
| `Аудит 2026-09/` | матеріали великого аудиту й промт до нього |
| `Get Stronger/_видалити/` | приймальник для прибраного з репозиторію. Що там і чому — `ЩО ТУТ І ЧОМУ.md` усередині |

Дві речі, які вже зʼясовували й не варто зʼясовувати вдруге:

- **Клік-трекінг Brevo вимкнути неможливо** на безкоштовному й
  стандартному планах. Єдиний доступний важіль — «Anonymous email
  tracking», і він не спиняє переписування посилань. Полагоджено в
  застосунку: екран «Посилання не спрацювало» з кнопкою перезапиту.
- **Захист від злитих паролів у Supabase — тільки на плані Pro.** Це не
  «одна галка», як здається з дашборда.

## 8. Куди дивитись, якщо щось зламалось

| Симптом | Де причина буває найчастіше |
|---|---|
| Публікація каже «Repository not found» | токен протух. Репозиторій **приватний**, і GitHub для приватного відповідає «не знайдено» замість «немає доступу». Запусти «Токен GitHub.command» |
| Публікація каже «немає звʼязку» | це справді мережа. Коміти на диску, нічого не втрачено |
| Сторінка біла, у консолі «Cannot read properties of undefined» | забутий `<script>` у розмітці. Гігієна ловить це для `date-core`, але не для всього |
| Листи з реєстрації не доходять | Supabase → Authentication → URL Configuration і шаблони. Див. `docs/EMAIL.md` |
| Тести зелені, а на екрані порожньо | модуль не підключений у HTML. Саме для цього існують браузерні перевірки |
| `npm test` каже «# fail 0», але код виходу 1 | **упав цілий файл тестів** на завантаженні. Лічильник цього не показує — дивись вивід повністю |
| Перевірка висить і падає по тайм-ауту | вона шукає розмітку, якої вже немає. Не «флак» — застаріла перевірка |

## 9. Чого НЕ робити

Повний список — `AGENTS.md`, розділ 1. Чотири найдорожчі:

1. **Не міняти схему бази руками в дашборді.** Тільки файлом міграції.
2. **Не рахувати рейтинг у клієнті.** Він серверний навмисно: те, що
   можна приписати собі в `localStorage`, не варте нічого.
3. **Не робити другу копію того, що вже є.** Другий `keyOf`, друга
   картка, другий набір CSS — усе це розходиться з оригіналом на першій
   же правці. Найдорожчий приклад: `mondayOf` жив у чотирьох файлах із
   чотирма різними реалізаціями, поки не зʼявився `js/date-core.js`; а
   питання «чи був цього дня тренувальний день» уміли відповідати два
   файли по-своєму, поки не зʼявився `js/daylog-core.js`. Тепер за цим
   стежать перевірки 14 і 15 гігієни.
4. **Не додавати залежність на фронтенді.** Жодної. Це не аскеза: саме
   тому сайт відкривається подвійним кліком і не протухає.
