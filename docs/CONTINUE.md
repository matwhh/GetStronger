# Як продовжити роботу

Цей файл — для того моменту, коли ти повертаєшся до проєкту через місяць
і не пам'ятаєш нічого. Або коли відкриваєш новий чат і треба ввести
нейронку в курс справи за одну хвилину.

Він не пояснює, **як усе влаштовано** — для цього є `AGENTS.md` і
`docs/MAP.md`. Він пояснює, **з чого почати й у якому порядку**.

---

## 1. Найкоротший шлях

```bash
cd ~/Desktop/Get\ Stronger/Get\ Stronger
open index.html          # сайт відкривається з файлу, збірки немає
```

Усе. Ні `npm install`, ні сервера, ні змінних оточення. Сайт — статичний,
дані лежать у `localStorage`, і без акаунта працює все, крім рейтингу.

## 2. Чотири кнопки, якими все робиться

Лежать у корені проєкту, клацаються двічі в Finder.

| Кнопка | Що робить |
|---|---|
| **Опублікувати.command** | ганяє тести й гігієну, комітить, відправляє на GitHub. Vercel збирає сайт сам. Якщо тести червоні — **нічого не відправляє** |
| **Токен GitHub.command** | коли публікація каже «немає доступу»: відкриє сторінку створення токена з проставленими правами, прийме його, покладе в Зв'язку ключів і одразу опублікує |
| **Прибрати-сміття.command** | чистить локальні тимчасові файли |
| **Увімкнути-CI.command** | вмикає прогін GitHub Actions на цьому клоні. Разова дія |

Кнопка публікації **показує список комітів, які поїдуть**, перш ніж
відправляти. Якщо вона каже «публікувати нічого» — значить усе вже на
GitHub.

## 4. Робочий цикл

Один і той самий, завжди:

```bash
# 1. змінив код

npm test                      # юніти, секунди
node tools/ci-hygiene.mjs     # гігієна репозиторію, миттєво

# 2. якщо чіпав те, що видно на екрані:
node tools/verify<щось>.mjs   # потрібна перевірка, ~30 с
bash tools/ci-browser.sh core # 12 найважливіших наборів, ~7 хв

# 3. кнопка «Опублікувати.command»
```

**Правило, яке рятує найчастіше:** нова перевірка мусить **впасти** без
твого виправлення. Якщо вона зелена і до, і після — вона нічого не
стереже, і ти дізнаєшся про це в найгірший момент.

## 5. Що живе поза репозиторієм

Код — це не весь проєкт. Три сервіси, до яких потрібні твої акаунти:

| Сервіс | Що там | Коли треба лізти |
|---|---|---|
| **Supabase** (`sojbyoxcxyiollefupss`) | база, авторизація, рейтинг, `pg_cron` | міграції, тексти листів, адреси перенаправлення |
| **Vercel** | хостинг | нічого робити не треба: збирає сам на кожен пуш |
| **Brevo** | надсилання листів (SMTP для Supabase) | майже ніколи |

Правила зміни бази — у `db/README.md`. Коротко: **у продакшені руками
нічого не міняють**, усе через файл міграції, і `db/live-schema.sql`
оновлюється після.

## 7. Куди дивитись, якщо щось зламалось

| Симптом | Де причина буває найчастіше |
|---|---|
| Публікація каже «Repository not found» | токен протух. Репозиторій **приватний**, і GitHub для приватного відповідає «не знайдено» замість «немає доступу». Запусти «Токен GitHub.command» |
| Публікація каже «немає зв'язку» | це справді мережа. Коміти на диску, нічого не втрачено |
| Сторінка біла, у консолі «Cannot read properties of undefined» | забутий `<script>` у `<head>`. Гігієна ловить це для `date-core`, але не для всього |
| Листи з реєстрації не доходять | Supabase → Authentication → URL Configuration і шаблони. Див. `docs/EMAIL.md` |
| Тести зелені, а на екрані порожньо | модуль не підключений у HTML. Саме для цього існують браузерні перевірки |
| `npm test` каже «# fail 0», але код виходу 1 | **упав цілий файл тестів** на завантаженні. Лічильник цього не показує — дивись вивід повністю |

## 8. Чого НЕ робити

Повний список — `AGENTS.md`, розділ 1. Три найдорожчі:

1. **Не міняти схему бази руками в дашборді.** Тільки файлом міграції.
2. **Не рахувати рейтинг у клієнті.** Він серверний навмисно: те, що
   можна приписати собі в `localStorage`, не варте нічого.
3. **Не робити другу копію того, що вже є.** Другий `keyOf`, друга
   картка, другий набір CSS — усе це розходиться з оригіналом на першій
   же правці. Найдорожчий приклад: `mondayOf` жив у чотирьох файлах із
   чотирма різними реалізаціями, поки не зʼявився `js/date-core.js`.
   Тепер за цим стежить перевірка 14 у `tools/ci-hygiene.mjs`, а цілий
   розділ звіту `docs/audit/2026-09-12/AUDIT.md` — про те, скільки такі
   дублі коштували.
