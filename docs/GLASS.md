# Скло Get Stronger

Як зроблено оформлення: чому воно виглядає саме так, із чого складається
кожна поверхня і що станеться, якщо зробити «як здається логічно».

Читати варто до того, як додавати нову скляну поверхню. Скло тут — не
декор, а **значення**: воно позначає предмет, який можна взяти. Якщо
склом стане все, скло перестане щось означати.

---

## 1. Три різні речі, які всі називають «склом»

У проєкті їх рівно три, і плутати їх не можна — у них різна ціна й різні
обмеження.

| | Де | Чим зроблено | Ціна |
|---|---|---|---|
| **Матова поверхня** | картки, плитки, кубики, пігулки | CSS: `backdrop-filter: blur()` + градієнт + два канти | майже нуль |
| **Скляний жетон** | значок рівня в шапці й на «Рейтингу» | дев'ять шарів `box-shadow` на колі | нуль |
| **Рідке скло** | нижня панель розділів на телефоні | SVG-фільтр `feDisplacementMap` у `backdrop-filter` | шар композиції + canvas |

Далі — кожна окремо.

---

## 2. Матова поверхня — `.card--glass`, `.kpi`, `.tile`, `.twt`, `.pill`

Основна й найчастіша. Живе в `css/style.css`.

```css
.card.card--glass, .kpi, .tile, .twt, .pill {
  position: relative;
  background: linear-gradient(158deg,
    rgba(var(--fx-rgb), 0.11) 0%,
    rgba(var(--fx-rgb), 0.045) 46%,
    rgba(var(--fx-rgb), 0.025) 100%);
  backdrop-filter: blur(16px) saturate(1.05);
  -webkit-backdrop-filter: blur(16px) saturate(1.05);
  border-color: rgba(var(--fx-rgb), 0.15);
  box-shadow: inset 0  1px 0 rgba(var(--fx-rgb), 0.18),
              inset 0 -1px 0 rgba(0, 0, 0, 0.40);
}
```

Чотири складники, і кожен відповідає за своє:

**Градієнт під кутом 158°** — це не заливка, а **товща скла**. Він майже
прозорий (0.11 → 0.025): угорі скла «більше», донизу воно тоншає. Саме
нахил градієнта створює відчуття пластини, покладеної під кутом до
світла.

**`backdrop-filter: blur(16px)`** — розмиття того, що ПОЗАДУ. Саме цим
скло відрізняється від напівпрозорого прямокутника: воно не просто
пропускає фон, воно його спотворює.

**`saturate(1.05)`** — ледь піднята насиченість фону. Реальне скло трохи
підсилює колір; без цього поверхня читається як пластик.

**Два внутрішні канти** — світлий зверху, чорний знизу. Це весь об'єм:
верхній кант — блик на фасці, нижній — тінь під нею. Разом вони роблять
із плоского прямокутника пластину завтовшки в один піксель.

### Чому звичайна `.card` лишається матовою

Навмисно. Скло позначає **предмет, який можна взяти**: картку вибору,
плитку з числом, кубик трекера. Звичайна картка з текстом — не предмет,
а абзац у рамці. Якщо зробити склом усе, зникне саме те, заради чого воно
є.

## 3. Блик, який іде за курсором

Скло без світла — сіра пластина. Світло тут одне й рухоме: пляма, що
йде за курсором.

```css
.card--glass::after, .kpi::after, .tile::after {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  pointer-events: none;
  background: radial-gradient(var(--spot-w, 220px) var(--spot-h, 180px)
    at var(--spot-x, 50%) var(--spot-y, 0%),
    rgba(var(--fx-rgb), 0.13), transparent 68%);
  opacity: 0;
  transition: opacity 0.25s var(--e-out);
}
.card--glass.is-hot::after { opacity: 1; }
```

Координати плями (`--spot-x`, `--spot-y`) пише JavaScript
(`App.initTilt` у `js/app.js`) — на `mousemove` по поверхні.

**Блик — ОКРЕМИЙ шар (`::after`), а не тінь на самому елементі.** Через
це поверхня мусить бути системою координат для нього:
`position: relative`. У `.card` це вже було, плиткам довелось дописати.

**Вміст піднімається над бликом:**

```css
.card--glass > *, .kpi > *, .tile > * { position: relative; z-index: 1; }
```

Без цього рядка текст лежав би ПІД плямою й на наведенні блід.

### Приглушення сусідів

Разом із бликом це і є «фокус»: у сітці з чотирьох карток видно, яку саме
ти зараз розглядаєш.

```css
.card--glass.is-cold { opacity: 0.5; --tilt-s: 0.975; }
```

Важлива деталь: `js/app.js` бере в холодні **тільки сусідів по спільному
батьку**, а не все скло сторінки. Гасити половину екрана через наведення
на одну плитку — це не фокус, а миготіння.

## 4. Нахил

`transform: perspective(900px) rotateX() rotateY()` на наведенні. Кут
рахується від позиції курсора всередині поверхні.

**900px перспективи — на самій поверхні, а не на сітці.** Спільна
перспектива нахиляла б крайні картки сильніше за середні: вони далі від
центра «камери».

**`--tilt-k` — коефіцієнт.** Ті самі 7° на плитці 150×90 виглядають
різкіше, ніж на картці 300×200: кут той самий, а шлях кутика вдвічі
коротший. Плитки беруть три чверті кута.

**`will-change` стоїть ТІЛЬКИ на гарячій поверхні.** Це не мікрооптимізація:
`will-change` піднімає елемент на власний шар композиції, і п'ятнадцять
плиток на «Прогресі» означали б п'ятнадцять шарів у спокої. Тепер шар
створюється в мить наведення й зникає, щойно курсор пішов.

## 5. Скляний жетон рівня

`js/app.js`, функція малювання значка рівня; стилі — `.lvl-ico` в CSS.

Кулька 39–40 px, усередині дуга-шкала й число. Скляною її роблять
**дев'ять шарів `box-shadow`**, а не заливка:

```css
.lvl-ico {
  font-size: 40px;              /* = ширина оправи */
  box-shadow:
    0 0 0.2em rgba(0,0,0,0.10),                                   /* м'яка тінь   */
    0 0.05em 0.15em rgba(0,0,0,0.35),                             /* тінь падіння */
    inset  0.075em  0.075em 0.0125em -0.0875em rgba(var(--tint-rgb),0.09),
    inset -0.075em -0.075em 0.0125em -0.0875em rgba(var(--tint-rgb),0.85),
    inset  0.025em  0.025em 0.025em -0.0125em rgba(var(--tint-rgb),0.6),
    inset -0.025em -0.025em 0.025em -0.0125em rgba(var(--tint-rgb),0.6),
    inset 0 0 0.05em 0.03em rgba(var(--tint-rgb),0.05),
    0 0 0.3em rgba(0,0,0,0.15);
}
```

Читається це так: дві зовнішні тіні (об'єм і падіння), два широкі
внутрішні канти (протилежні кути — лінія зламу скла), два вузькі
внутрішні (сама фаска), вузьке внутрішнє світіння (межа канта).

### Дві речі, на яких тут легко помилитись

**Одиниці `em`, а не `px`.** Значення розраховані на елемент ~40 px. У
пікселях на кульці 96 px той самий кант виглядав би ниткою. `em`
рахується від `font-size` жетона, який дорівнює його ширині — тож кант
масштабується разом із кулькою.

**Кулька ПРОЗОРА, а не залита.** Тіло — 0.08 угорі, 0.03 унизу. Це натяк
на товщу скла, а не сіра пляма. Скло не має власного кольору: усередині
видно те, що позаду, і на чорній сторінці всередині буде чорно — так і
мусить бути.

> Спроба зробити «мутність» заливкою вже була: 0.16 у середині. Диск
> ставав сірим кружком, а не склом, і заразом з'їдав контраст — на картці
> (`#171717`) найтемніша дуга падала до **3.08:1** при межі 3:1. Тепер
> заливки майже немає: **4.3:1** найгірша дуга, **13:1** цифра.

**Широкого внутрішнього світіння тут немає.** В оригінальному рецепті
воно 6 px при 12 % білого; на картці 300 px це край, на кульці 39 px —
половина площі, тобто засвіт по всьому склу. Чисте скельце має край, а не
сяйво зсередини.

## 6. Рідке скло — нижня панель на телефоні

`js/liquid-glass.js` + `js/tabbar-glass.js`. Єдине місце в проєкті.
Обидва файли вантажаться **ліниво**, з `js/app.js`, і лише коли панель
справді потрібна.

### Як це працює

На `<canvas>` малюється **карта зміщення**: у канал R пишеться зсув по X,
у G — по Y, значення 128 = нуль. Карта віддається в `feDisplacementMap`
через `feImage` (data-URL), а весь фільтр вішається на елемент як
`backdrop-filter: url(#id)`.

У карті складені два доданки:
- **радіальне збільшення** — лінза;
- **зсув по нормалі на фасці** — заломлення краю.

Разом вони дають те, що в iOS називають «рідким склом»: фон під панеллю
не просто розмитий, а **зміщений і збільшений**, як під справжньою
лінзою.

### Три пастки, які коштували найдорожче

**1. Backdrop root.** `backdrop-filter` бачить лише те, що намальовано в
межах свого backdrop root, а створює цей root **будь-який предок** із
`filter`, `opacity < 1`, `mask`, `mix-blend-mode`, `isolation` або
`contain: paint`.

> Скляний елемент **не можна класти всередину іншого скляного** — він
> заломлюватиме порожнечу. Саме тому лінза панелі лежить *сусідом* до
> самої панелі, а не в ній.

**2. Прозорість анімується на шарах, а не на склі.** `opacity < 1` на
самому елементі робить його backdrop root **посеред анімації**, і
заломлення блимає. `transform` безпечний — його немає в переліку вище.

**3. Safari і Firefox не підтримують SVG-фільтр усередині
`backdrop-filter`.** Шар заломлення там просто не малюється, лишається
матова капсула з кантом. Це прийнятний фолбек, і саме тому шар винесено
окремим `div` — щоб його відсутність нічого не ламала.

### Чому файл не переписаний «під свій стиль»

`liquid-glass.js` прийшов готовим пакетом і вставлений майже без змін —
навмисно. Це не бізнес-логіка Get Stronger, а **оптика**: формула карти
зміщення, підібраний профіль фаски, точний `scale` фільтра. Переписати її
означало б переписати математику, у якій кожне число вивірене; правки
звелися б до косметики й ризику.

Єдине, що в ньому змінено проти пакета, — коментар угорі. Файл лишається
копією, яку можна оновити одним перезаписом.

## 7. Як додати нову скляну поверхню

1. **Спитати себе, чи це предмет.** Якщо ні — лишити матовою `.card`.
2. Дописати селектор у спільний блок `.card.card--glass, .kpi, .tile,
   .twt, .pill` — **не копіювати правила**. Скопійований набір
   розійдеться з оригіналом на першій же правці палітри.
3. Якщо потрібен блик — дописати селектор і в блок `::after`, і в
   `> * { z-index: 1 }`.
4. Якщо поверхня клікабельна й нахиляється — переконатись, що
   `App.initTilt` її бачить (він шукає за класами).
5. Перевірити на телефоні: `node tools/verifyresponsive.mjs`.
6. Перевірити контраст тексту на новому фоні. У проєкті межа — **4.5:1**
   для тексту й **3:1** для великих елементів; скло з'їдає контраст
   помітніше, ніж здається.

## 8. Змінні, які все це тримає

| Змінна | Що це |
|---|---|
| `--fx-rgb` | колір скла в RGB-каналах (для `rgba()` з різною прозорістю) |
| `--tint-rgb` | колір кантів і полиску жетона |
| `--glass`, `--glass-2` | непрозорі підкладки шапки й підвалу |
| `--spot-x`, `--spot-y`, `--spot-w`, `--spot-h` | позиція й розмір блика (пише JS) |
| `--tilt-k`, `--tilt-s` | коефіцієнт нахилу й масштаб приглушеної поверхні |
| `--e-out` | крива згасання переходів |

Усі оголошені в `:root` на початку `css/style.css`. Темніша тема
(`prefers-color-scheme`) перевизначає `--glass` і `--glass-2` — і більше
нічого: скло тримається на світлі, а не на кольорі.
