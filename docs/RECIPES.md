# RECIPES — як зробити типову зміну

Покроково, з файлами й перевірками. Кожен рецепт закінчується тим, що
запустити, — і це не формальність: у проєкті немає ручного QA, перевірки
є єдиним, що ловить регресії.

Правила й заборони — [`../AGENTS.md`](../AGENTS.md).
Де що лежить — [`MAP.md`](MAP.md).

Загальне для всіх рецептів:

```bash
node --check js/файл.js      # після кожної правки JS
npm test                     # перед комітом, завжди
node tools/ci-hygiene.mjs    # перед комітом, завжди
```

## 1. Додати сторінку

1. Скопіювати каркас найпростішої сторінки (`cardio.html` — гарний
   зразок: мінімум своїх скриптів). Замінити `<title>`, опис і вміст
   `<main>`.
2. Лишити **спільний префікс скриптів** без змін і в тому ж порядку
   (перелік — `MAP.md` §1). Свій скрипт додати останнім.
3. Створити `js/назва.js` за шаблоном IIFE:
   ```js
   (function () {
     'use strict';
     const { $, esc } = window.App;
     // …
   })();
   ```
4. Якщо сторінка має бути в меню — додати запис у `NAV_GROUPS`
   (`js/app.js`, ~рядок 266). Поля: `href`, `label`, `icon`, `core`
   (true = ще й у нижній панелі на телефоні), `children` для групи.
   **Іконку** треба додати у `navIcon()`/`tabIcon()` там же.
5. Довідка: додати розділ у `js/help-content.js` під ключем = імʼя файла
   сторінки. Без нього книжка в шапці буде прихована.
6. `node tools/build-meta.js` — впише `canonical`, `og:url` і додасть
   сторінку в `sitemap.xml`.
7. Якщо сторінка має працювати офлайн — вона вже працює: SW кешує
   оболонку. Але перевір `verifysw`.

```bash
node tools/verify7.mjs          # 16 сторінок × 2 ширини: overflow і JS-помилки
node tools/verifyhelp.mjs       # книжка є на кожній сторінці
node tools/verifya11y.mjs
```

## 2. Додати графік

**Стандарт: графік — це лінія з крапками. Стовпчиків немає ніде.**
Причина в `ENGINEERING.md` §14: жоден показник Get Stronger не має осмисленого
нуля в масштабі свого графіка.

1. Порахувати шкалу спільною арифметикою з `js/journal.js`:
   `chartScale(lo, hi)` → `chartRows(sc)`. Вона дає 12% повітря, крок
   ряду 1/2/5×10ⁿ і не більше шести рядків сітки.
2. Малювати чотири речі в цьому порядку: сітка з підписаною лівою
   шкалою → заливка під лінією → лінія → крапки.
3. Підказку при наведенні підключити `wireChartTip(boxSel, tipSel)`.
4. Щільність крапок: `dr = clamp(2, 3.5, pitch * 0.34)`.

**Не** прорідити готовий ряд сітки, щоб влізти в шість, — це ламає
рівність кроків (76·80·84·86 замість 75·80·85·90). Крок піднімають доти,
доки рядків не стане шість.

```bash
node tools/verifyexercise.mjs   # блок 12 падає на будь-якому <rect>, що не зона наведення
node tools/verifyhistory.mjs    # блок 24 — те саме
```

## 3. Додати календар днів

Не малювати свою сітку. `js/daycal-core.js`:

```js
DayCal.html({
  from: '2026-09-01',   // перший день вікна
  to:   '2026-09-09',   // останній ДІЯЛЬНИЙ день; далі — бліді
  until:'2026-11-30',   // (опц.) докуди тягнути сітку вперед
  cls:  'mt-2',
  label:'Календар сезону',
  cell: (key, date, isFuture) => ({ lvl, sel, label, attrs }) // або null
})
```

Модуль знає лише геометрію тижнів і місяців. Що означає заливка —
вирішує колбек `cell()`. **Але заливка вже має значення на двох інших
екранах** («цього дня я тренувався»), тож третій сенс треба або
узгодити, або підписати.

```bash
node tools/verifydaycal.mjs     # звіряє структурні відбитки всіх календарів сайту
```

## 4. Додати продукт у довідник

`js/foods.js`, масив `FOODS`. Форма запису:

```js
{ id:'chicken-breast', group:'protein', name:'Куряче філе (грудка)',
  alias:'курка кура куряча грудка',      // для пошуку
  state:'raw', yield:0.73,               // сире → готове
  per100:{ kcal:120, p:22.5, f:2.6, c:0 },
```

`id` — назавжди: він лежить у профілях користувачів. Перейменувати можна
`name`, але не `id`.

## 5. Додати трекер

`js/tracker-core.js`, обʼєкт `TRACKER_DEFS`:

```js
water: { type:'water', name:'Вода', kind:'cumulative', unit:'л',
         min:0, max:15, presets:[0.25, 0.5, 1], defaultGoal:2.5 }
```

`kind` буває: `cumulative` (додається за день), `duration` (хвилини),
`scale` (1..10), `count`. Межі `min`/`max` живуть тут, а не в полі вводу
— екран бере їх звідси.

```bash
node --test tests/tracker-core.test.js
node tools/verifytrackerspage.mjs
```

## 6. Додати поле в профіль

1. `blankProfile()` у `js/store.js` — єдине джерело форми профілю.
2. **`SCHEMA_VERSION` піднімати НЕ треба**, якщо це просто нове поле.
   Піднімати — лише коли міняється СТРУКТУРА (поле переїхало, змінився
   тип, перейменування ключів). Тоді ще й крок у `migrate()`.
3. Якщо поле особисте — додати ключ у `PERSONAL_KEYS`, інакше воно не
   почиститься при виході й перетече в чужий акаунт.
4. Якщо поле редагується — місце для цього одне: `account.html`.

```bash
node --test tests/store-core.test.js tests/sync-owner.test.js
node tools/verifyroundtrip.mjs   # Export → Clear → Import поле за полем
node tools/verifydata.mjs
```

## 7. Змінити щось у базі

**Порядок обовʼязковий, коротких шляхів немає.**

1. Прочитати чинне визначення в бойовій базі (`pg_get_functiondef`,
   `\d+`), покласти його у `db/<назва>-rollback.sql`.
2. Переконатись, що від обʼєкта ніхто не залежить: індекси, дефолти,
   `CHECK`, тригери, інші функції.
3. Написати міграцію файлом `db/<назва>.sql`.
4. Застосувати **тим самим текстом** через `apply_migration` з
   осмисленою назвою.
5. Перезняти знімок: `db/dump-live-schema.sql` → оновити
   `db/live-schema.sql`.
6. Закомітити міграцію, rollback і знімок одним комітом.

Будь-яка перевірка, що пише, — тільки в `BEGIN … ROLLBACK` з
`RAISE EXCEPTION` для результату.

```bash
node tools/verify-sql-suites.mjs      # 92 SQL-перевірки на копії схеми
node tools/verify-schema-perms.mjs    # справжні запити клієнта: GRANT і RLS
node tools/verify-elo-week.mjs
```

## 8. Змінити правила ELO

Числа живуть у **двох місцях і мусять збігатися**: таблиця `elo_config`
в базі та її дзеркало `db/elo-config.json`. Розходження ловить
`tests/elo-config-sync.test.js`.

Клієнтська математика — `js/elo-core.js`, серверна — `db/elo-engine.sql`.
Паритет між ними стереже `tests/elo-parity.test.js` з фікстурами,
згенерованими `tools/gen-elo-parity.mjs`.

```bash
node --test tests/elo-*.test.js
node tools/simelo.mjs        # баланс сезону; має лишатись 6/6
```

Зміна правил, які видно користувачеві (скільки коштує дія, коли
закінчується сезон), — **питати власника**, а не вирішувати самому.

## 9. Змінити оформлення

Токени — угорі `css/style.css`: поверхні, текст, акцент, семантична
палітра (макроси, групи мʼязів, стани). Колір у Get Stronger означає ДАНІ та

## 10. Зробити скло

У проєкті два різні «скла», і вони не взаємозамінні.

**Поверхня** (картка, шапка, нижня панель) — `backdrop-filter` плюс
градієнт і дві грані. Зразок — `.card--glass`.

**Дрібний предмет** (жетон рівня) — край, а не заливка: багатошаровий
`inset box-shadow` у `em`, тіло майже прозоре. Зразок — `.lvl-ico`.

Головна пастка: **`backdrop-filter` не бачить нічого крізь предка, у
якого він теж є.** Предок із `filter`, `opacity < 1`, `mask`,
`mix-blend-mode`, `isolation` або `contain: paint` створює backdrop root
— і скло всередині заломлює порожнечу. Саме тому лінза нижньої панелі —
СУСІД `<nav>`, а не її дитина.

```bash
node tools/verifytabbar.mjs      # включно з виміром реальної різкості фону
node tools/verifylevelicon.mjs
node tools/verifytilt.mjs
```

## 12. Знайти, чому щось зламалось

| Симптом | Куди дивитись |
|---|---|
| біла сторінка | `rescue()` в `app.js`; консоль; `errors.js` шле в Sentry |
| після деплою старий JS із новим HTML | `sw.js` — звірка HTML і повне знесення кешу; `?nosw=1` як аварійний вимикач |
| дані «зникли» | `ib.profile.backup*`, `ib.profile.corrupt.*`, `ib.pending` у localStorage |
| рейтинг не рахується | `elo-api.js` → RPC `elo_state`; далі логи Supabase |
| дата зʼїхала на день | шукати `toISOString()` — його не має бути в ключах дня |
| скло перестало бути склом | предок став backdrop root (рецепт 10) |
| перевірка «зелена», а баг є | перевірка дивиться на клас, а не на намальоване; міряти пікселі |
